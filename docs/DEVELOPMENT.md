## Distribution Architecture

This repository does not enable GitHub Pages or create a standalone source directory
website. Git stores import indexes, Markdown source directories, and distribution tools.
GitHub Releases stores already-published encrypted `.kyyrule` and `.kyybundle` files.
It does not store manga or video content, plaintext rules, executable extensions,
account credentials, cookies, tokens, decryption keys, or private signing keys.

## Indexes and Legacy Compatibility

Collection entry points advance with releases, but each package URL inside a collection
is pinned to a specific Release tag to prevent mixing versions during an update.
In **this repository**, `sources.json` is a compatibility alias of `all.json`.
The older repository's `sources.json` uses a different discovery format and is not
rewritten here. Existing app checks for size, SHA-256, signatures, decryption, and
locked rules remain in place.

Existing `/v1/rule-catalog`, `/v1/rule-packages/<release>/<id>.kyyrule`,
`/v1/rule-bundles/<release>/<channel>.kyybundle`, and `/rules/<id>` distribution paths
remain unchanged, as do the older discovery-format `sources.json` and its Pages/raw
mirrors. Keeping a domain for compatibility is not creating a new directory website;
this repository adds a GitHub distribution channel.

## Publication and Update Boundaries

1. Keep the existing private rule review, signing, encryption, and production release workflow unchanged.
2. Read only publicly released collections and encrypted packages. Do not access private rule sources, decrypt, or re-sign packages.
3. Require matching full/general collection versions and the exact non-adult subset. Verify the size and SHA-256 of every package and bundle.
4. Re-read upstream collections before publication to detect an upstream release change during synchronization.
5. Upload files to a draft Release. Verify every asset's GitHub-reported SHA-256 before publishing and advancing `latest`.
6. Update collection indexes and generated directories on `main` only after publication. Reject sequence rollback, changed content at the same sequence, and rewrites of published assets.
7. GitHub Actions synchronizes every six hours and also supports manual runs. A failure before promotion leaves the previous Release and entry points unchanged; a later index update failure leaves the previously committed indexes in place.

The synchronization tool checks encrypted/signature **structure** and integrity only.
It does not claim cryptographic signature verification; the app's existing import
path remains responsible for signature verification and decryption.
Neither test keys nor production keys are stored in this repository.

## Generated Source Directories

The default README, source directories, and maintenance guide are in English. Each
page has English / Simplified Chinese / Japanese links at the top. Chinese pages use
the `.zh-CN.md` suffix; Japanese pages use `.ja.md`. Links to directories, the README, and the maintenance guide stay
in the selected language. Switching navigates between GitHub Markdown files; it
does not require JavaScript, browser language detection, or GitHub Pages.

English directories are `SOURCES.md` (regular sources) and `docs/SOURCES_ADULT.md`
(a separate adult directory). Their Chinese counterparts are `SOURCES.zh-CN.md`
and `docs/SOURCES_ADULT.zh-CN.md`; Japanese pages are `SOURCES.ja.md` and
`docs/SOURCES_ADULT.ja.md`. All six are deterministically generated by
`scripts/generate_source_directory.py` from this repository's `all.json` and
`general.json`. Do not add or remove entries by hand.

Names, rule IDs, and content ratings come from the public collections. Generation
does not read plaintext rules, decrypt packages, contact source websites, or add
a website backend, QR codes, or an app-launch protocol. All three languages share the
same rule IDs, ordering, counts, stable import URLs, and pinned URLs. Only interface
text, table headings, rating labels, and action labels are translated; original
source names are preserved.

The generator reuses collection schema and pinned-URL validation. It requires
matching versions, catalog sequences, and the exact non-adult subset. External names
are escaped as text to avoid breaking tables or injecting Markdown links or HTML.
Entries sort by case-insensitive name and rule ID. Removed sources disappear from
newly generated directories.

- "Import link": `https://github.com/manga-rule-community/sources/releases/latest/download/<id>.kyyrule`,
  for users to copy into an app. It targets the latest Release at retrieval time and
  promises neither automatic installation nor automatic updates after installation.
- "Download this version": the collection's existing version-pinned URL, for the
  package corresponding to the directory snapshot.
- `safe`, `teen`, and `mature` belong in the regular directory; `adult` appears only
  in the separate adult directory. Ratings are not age verification and do not
  establish content authorization, website availability, or app review or endorsement.

After uploading, verifying asset hashes, and publishing a Release, the synchronization
workflow generates directories from the collections in `dist`. It commits all six
directories together with the four metadata files. Directories are not Release assets
and do not rewrite published packages or checksums.
Both CI and the pre-synchronization check run `--check`, which fails on missing or
stale directories without writing files.

## Local Validation

Run these commands from the repository root.

Requirements: Python 3.11+ and curl; publication also requires GitHub CLI.
There are no third-party Python dependencies.

```sh
python3 -m unittest discover -s tests -v
python3 scripts/generate_source_directory.py --check
# After changing the generator, regenerate and commit all six Markdown directories:
python3 scripts/generate_source_directory.py
python3 scripts/mirror_release.py --output dist/preview
# Optional preview from prepared collections; no tracked directory or live release changes:
python3 scripts/generate_source_directory.py --catalog-dir dist/preview --output-dir dist/directory-preview
# Only the explicit --publish flag writes to GitHub Releases:
python3 scripts/mirror_release.py --output dist/release --publish
```

Use an empty output directory for each mirror run. To publish after a preview, run
again with a different empty output directory. Do not commit `dist/`.
After successful publication, `all.json`, `general.json`, `sources.json`,
`publication.json`, and the six English/Chinese/Japanese directories are synchronized to Git.
This repository's `GITHUB_TOKEN` needs only `contents: write`; no app-repository token,
Cloudflare key, app-signing certificate, or App Store Connect credentials are required.
